# Codex 部署提示词

部署对象为 AI交易守望站 V3.2 功能增强版，package.json 版本 1.1.0。请在我明确授权的服务器范围内实施。不要覆盖现有数据库、删除上传文件或重建数据卷。此次代码修复不等于服务器已验收。

1. 阅读 README、PRD、Dockerfile、docker-compose.yml、.env.example 和测试交付说明，先核对目标运行时、CPU/RAM、磁盘、端口、反代链路及回滚方案。
2. 新站使用空库初始化；旧站先备份数据库、上传和表情卷并验证可恢复。v1.0.1 升级必须在备份后执行一次 database/migrations/007-v3.2-pins.sql，新安装的 schema 已包含字段，不再执行007，禁止覆盖旧库运行全量 schema，禁止执行 docker compose down -v。
3. 填写 production 环境、HTTPS PUBLIC_ORIGIN、DB/Redis 独立随机密码、至少64位十六进制 DONATION_CONFIG_HMAC_KEY、真实 Turnstile 和 SMTP。不要打印 .env、密码、token 或重置链接。
4. package-lock.json 已提供，使用 npm ci；不要重新 npm install 改写锁文件。先 docker compose config --quiet，再构建并启动，确认 app、MySQL、Redis 健康；/api/live 只检查进程，/api/health 必须检查依赖。
5. TRUST_PROXY=1 仅对应一层受控反代，反代覆盖 X-Forwarded-For。存在 CDN/Tunnel 时按真实链路配置，验证不同客户端的 req.ip 独立，且访客不能伪造。反代翻译读取超时建议120秒，上传体积限制与5MB单图一致。
6. 在非 root app 用户下检查 uploads、stickers 两个目录可写；测试 JPG/PNG/WebP 重编码、伪装格式拒绝、私密证据隔离、下架图片失效、卷重启持久化。旧卷权限问题先备份再修复所有者，不删卷。
7. 核验注册、登录失败后验证码刷新、密码修改与邮件重置。普通管理员不能单条或批量处理其他管理员的举报/申诉/内容；审计写失败时数据必须回滚。测试 1/100/101 条、重复 ID 和混合结果。
8. 测试评论审核上下文和图片入口，不得泄露未公开父帖或私密证据；测试待审/已发布后台进入详情后返回原标签，下架后刷新原列表。确认时间按 UTC 传输、按浏览器时区显示。
9. 如启用翻译，使用 --profile translate，确认固定镜像、所需模型和 /api/translation/languages。分离翻译机只走私网，私网IP可配置，内部DNS需显式允许；端口仅允许网站机访问。验证长短帖、不同源语言、未安装模型、缓存命中、队列满429和服务重启。模型升级递增 TRANSLATE_MODEL_REVISION。
10. 按资源调整 app/translate 的容器限额；默认每Node进程2个翻译任务，多实例需汇总并发。对100/300/500活跃会话分级压测并记录指标；不将在线人数当作同时推理任务数。
11. 完成真实 SMTP、Turnstile、TLS、备份恢复、监控告警及部署后依赖审计。交付URL、容器健康、API/权限测试、备份与回滚位置，以及未验证事项；不要声明绝对安全或未实测的承载量。

服务器起步预算：网站8核16GB RAM/100–200GB SSD，独立翻译8核16GB至16核32GB/100–200GB SSD；多语言数量、文章长度和翻译并发决定最终配置。开放前以目标服务器压测为准。公开 GitHub 前按开源指南排除真实用户资料与所有密钥。

## V3.2 置顶与页脚联系方式

版本为 v1.1.0，研发名称 V3.2 功能增强版。本版基于已修复的 v1.0.1 增量修改，保留其余功能。外层五个文件沿用原文件名（包括 V3.1），以内部版本号识别本次更新。

| 功能 | 超级管理员 | 管理员 | 普通会员 |
| --- | --- | --- | --- |
| 社区首页置顶 | 可设置 | 禁止 | 禁止 |
| 首页之外的帖子列表置顶 | 可设置 | 可设置 | 禁止 |
| 页脚联系方式配置 | 可设置 | 禁止 | 禁止 |

进入管理员后台的「帖子置顶」标签；超管看到首页、板块两个独立开关，管理员仅看到板块开关。只允许处理已公开帖子，可搜索和翻页。板块置顶适用于举报曝光、交流讨论及各讨论栏目中本来符合筛选条件的帖子，不把帖子跨栏目复制。独立内容页没有帖子列表。搜索结果和「我的帖子」继续使用原顺序。置顶帖子优先显示，同组仍按新帖或热度排序；允许多条置顶。下架或驳回会清除两种置顶，重新发布时不自动恢复。新增板块置顶是管理员角色能力，可用于任意已公开作者的帖子；原有审核、删除及禁言的作者层级规则不变。

超管进入「超级管理员后台 → 页脚联系方式」，启用总开关，最多添加4行不同类型，左侧选 QQ、Telegram、X、TikTok、微信、Discord、WhatsApp、邮箱或其他，右侧填账号/号码。每行也可独立关闭；空行请关闭或移除。保存后在页脚底部中间竖向显示，手机端自动换行。关闭总开关后公开页为空，公开接口不返回后台保留的号码。配置带签名、版本冲突检查和审计，审计不保存号码。前端按纯文本显示，不执行填写内容中的 HTML。

默认两个置顶字段均为关闭，联系方式默认关闭且为空。不新增生产密钥，联系方式复用原 DONATION_CONFIG_HMAC_KEY，升级时必须保留原密钥。不要把本机体验账号或 .env 带到生产环境。

## 从 v1.0.1 升级到 v1.1.0

新安装使用空数据卷与最新 database/schema.sql，已包含置顶字段；不要再运行007。已有 V3.1 修复版先备份数据库、上传与表情卷并确认可恢复，停止 app 写入，**只执行一次 database/migrations/007-v3.2-pins.sql**，再更新镜像并启动 app。该脚本新增两个默认0的字段及索引，不删除原数据；已有数据卷不会自动迁移。更早版本先补齐此前缺失迁移。不要对生产旧库运行全量 schema.sql，也不要执行 docker compose down -v。

Linux / Docker Compose 下，在正确项目目录和已载入正式环境配置的前提下执行（已有 v1.0.1 数据库）：

```bash
docker compose stop app
docker compose exec -T db sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" exec mysql -u"$MYSQL_USER" "$MYSQL_DATABASE"' < database/migrations/007-v3.2-pins.sql
docker compose up -d --build app
docker compose ps
curl -fsS http://127.0.0.1:3000/api/health
```

确认迁移成功后再启动新版应用；遇到 Duplicate column 表示字段可能已存在，先核对数据库版本与字段，不盲目重跑。回滚应用可保留新增字段和原数据，数据库回滚按已验证备份方案实施，不直接删卷。验收超管/管理员/会员权限、置顶顺序、下架清除、联系方式关闭和并发保存。

本次本地真实 MySQL 已验证权限、排序、联系方式保存及旧表迁移；本机运行采用 development 和 REDIS_ENABLED=false，不等同于生产配置验收。新增功能不改变翻译引擎部署与服务器预算。
