# GitHub 开源首发指南

建议仓库名称 ai-trust-community。本次交付版本为 v1.0.1，研发名称保持 V3.1。仓库若从未发布，可直接以 v1.0.1 首次发布；已经发布 v1.0.0 的应新增修复 Release，不覆盖旧标签。

## 发布前核对

1. 检查拥有代码和素材的开源权利。代码 MIT，用户内容、第三方商标及外部 LibreTranslate 的许可需分别遵守，不将 MIT 等同于全部第三方资产的许可。
2. 不提交真实 .env、HMAC/SMTP/验证码密钥、生产地址配置、数据库、用户证据、上传文件和日志。保留 .env.example 中的空占位配置。
3. 提交 package-lock.json，使用 npm ci、npm test、npm audit --omit=dev。此次 sharp 0.35.5 的依赖审计为0条已知漏洞；公开前再次审计，因为公告会变化。
4. 更新后的离线 HTML 只供界面演示，真实服务须由 public/index.html 配合后端运行。不能把离线演示测试写成真实 MySQL/Redis/SMTP/翻译模型端到端通过。
5. 在真实目标服务器完成部署清单、权限和事务回滚、媒体隔离、翻译模型能力、邮件、备份恢复及容量压测。公开仓库不等于生产站点已经验收。

## 创建版本

在 GitHub 创建空仓库，确认 git status 与待提交文件后初始化 main、提交代码并添加真实远端。先推送分支，再创建 v1.0.1 标签和 Release。不要原样执行含占位符的 remote 命令；不要对既有仓库使用强制推送覆盖历史。

Release 说明应列出验证码重试、单条权限、审计事务、UTC日期、评论审核、翻译缓存及队列、健康检查和上传卷权限等修复，以及尚需真实环境验收的范围。建议启用分支保护、CI、Dependabot、私密漏洞报告及备份告警。
