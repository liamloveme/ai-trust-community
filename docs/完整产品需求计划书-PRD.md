# AI交易守望站｜完整产品需求计划书（PRD）

**产品版本：** 功能增强版 `v1.1.0`（研发迭代代号 V3.2）  
**文档性质：** 全量需求基线，不是历史补丁（包含 V3.1 批量审核及 V3.2 置顶、页脚联系方式模块）  
**产品定位：** AI 大模型账号、API Key、中转服务的公益交流与交易风险线索论坛  
**默认语言：** 简体中文；其余界面语言由用户手动选择，不根据 IP 或浏览器自动切换。  
**交付形态：** Node.js/Express + MySQL 8.4 + Redis 7 + 静态浏览器前端 + Docker Compose，可选 LibreTranslate。

## 1. 产品背景、目标与边界

现有 AI 大模型账号与 API Key 交易链路涉及号主、渠道、中间商、采购者。交易可能发生付款未交付、权限与期限争议、交付后失联、虚假担保等风险。平台提供非营利性公开交流、风险线索提交、证据脱敏、管理员审核、当事方申诉和纠错入口。

1. 使用户可以交流合法合规的 API 服务使用、账号交付和交易经验。
2. 为风险线索提供证据导向的审核流程，降低私人信息、未经证实指控传播概率。
3. 形成可追溯的管理员权限与操作审计，减少滥用删帖、随意禁言及捐赠地址篡改风险。
4. 提供不依赖商业支付网关的自愿加密货币捐赠展示，公开声明其非交易担保。
5. 提供多语言界面和开源可部署架构，方便社区自部署与二次开发。

**不在本版本范围：** 资金托管、支付担保、实名认证司法核验、自动判定诈骗事实、全自动翻译任何语言、视频上传、移动原生 App、基于站内评分作法律事实裁定。

## 2. 用户与角色

| 角色 | 读取公开内容 | 发帖/评论/上传 | 审核/下架/禁言 | 管理管理员 | 查看操作日志 | 编辑捐赠地址 |
|---|---|---|---|---|---|---|
| 游客 | 是 | 否 | 否 | 否 | 否 | 否 |
| 普通会员 | 是 | 是，受禁言和限流约束 | 否 | 否 | 否 | 否 |
| 普通管理员 | 是 | 是 | 仅获授权项目且仅限会员对象 | 否 | 仅本人 | 否 |
| 超级管理员 | 是 | 是 | 全部管理操作（除受保护超级管理员） | 是 | 全部人员 | 是，需重新验密 |

超级管理员权限不能在普通用户页面通过更改浏览器元素获得；管理入口按后端身份展现，所有 API 在服务端每次独立鉴权。管理员不能下架其他管理员内容、禁言管理员、任命管理员或浏览他人的日志。超级管理员继承所有管理功能。

## 4. 注册、登录、找回密码

- 用户以有效邮箱、社区昵称和至少 10 位密码注册；邮箱和昵称不可重复；生产环境必须开启 Turnstile。
- 登录仅一个入口，不允许从登录窗口人为选择“普通会员/管理员/超级管理员”。实际身份从数据库得出。
- 密码存储为随机盐哈希；登录成功创建随机会话令牌；会话 Cookie 使用 HttpOnly、SameSite 与生产 Secure；写请求校验 CSRF。
- 忘记密码使用注册邮箱发一次性链接：20 分钟有效、服务端仅存令牌哈希、使用后作废、不泄露邮箱是否存在；生产环境必须配置 SMTP。
- 已登录用户修改密码须输入旧密码；重置后撤销旧会话，修改后其他设备的会话失效。
- 超级管理员创建使用独立的手动初始化命令；正式环境**不得**创建 HTML 演示账号。
- 未接入邮箱所有权验证或多因素认证时，应在生产安全验收清单中标为待办，不能声称具备。

**验收标准：** 管理账号不能靠客户端切换产生；无效令牌无法重置；忘记密码接口不枚举邮箱；会话撤销后受保护 API 拒绝请求。

## 5. 帖子、分类和全站搜索

- 帖子类型：交流讨论、风险曝光。字段：UID、栏目、标题、正文、是否前台匿名、创建时间、状态、浏览量。
- 正文只允许安全文本及受控表情占位符，不执行 HTML 脚本；私密证据不得直接进入公开页面。
- 公开帖子支持搜索：标题、正文、作者和栏目；支持点击搜索及回车，结果为空需有明确反馈；支持清除关键词、分页和筛选。
- 讨论帖按规则公开；风险曝光与带图帖子需要审核；举报信息即使通过审核也不是平台事实认定。
- 发帖时公开图片最多 20 张，私密证据最多 20 张，评论图片最多 20 张，每张原文件最大 5 MB。支持 JPG/PNG/WebP 静态图片；拒绝视频、GIF、SVG。
- 上传对实际文件进行解码验证和重编码、随机文件名、不执行文件内容。公开图片与私密证据使用不同访问控制；超限应由前后端双重拒绝。
- 匿名展示仅隐藏公开昵称；平台数据库仍记录作者身份以用于申诉及合规审核。

**验收标准：** 正好第 20 张可保存，第 21 张被拒绝；媒体 API 不允许未获授权下载私密证据；评论不绕过禁言检查。

## 6. 详情页导航与审核回退（本次修复重点）

- 打开帖子详情前记录真实来源：`home`、`exposure`、`discussion`、`mine`、动态 `section`、普通管理员 `admin`、超级管理员 `super`。
- 记录来源所在后台的选中标签，如 `posts`、`published`，以及用户搜索、栏目、排序、分页和列表滚动位置。
- 点击详情页“← 返回列表”应回到所记录的**原列表**，而不是强行返回论坛首页。
- 从管理员「待审帖子」点击“核对内容”进入详情，返回仍在同一待审列表；「帖子管理/下架」同理。
- 从超级管理员同样的审核标签进入详情，也必须回到**超级管理员**原标签，不可降级到普通论坛。
- 从搜索、栏目、我的帖子进入详情时，恢复搜索词、栏目和当前筛选；提交评论后刷新详情不能覆盖来源。
- 若在详情执行“下架帖子”，应回到原后台标签并重新请求列表；前台来源需重新读取公开列表，确保下架内容不继续残留。
- 若返回时权限已被撤销或栏目已关闭，则安全回退至首页，不能因浏览器历史状态绕过鉴权。
- 服务端仍决定用户是否能查看未公开帖子；来源状态不作为授权凭据。

**验收标准：** 上述每一来源都用真实浏览器操作验证；帖子下架后的列表刷新和权限变更回退覆盖到自动化测试。

## 7. 公开图片、私密证据及评论

| 场景 | 数量上限 | 单个文件大小 | 可见范围 |
|---|---|---|---|
| 发帖公开图片 | 20 张 | 5 MB | 审核发布后可公开 |
| 发帖私密证据 | 20 张 | 5 MB | 作者、被授权审核者 |
| 单条评论附图 | 20 张 | 5 MB | 审核发布后随评论显示 |
| 自定义私人表情 | 最多收藏 200 张 | 1 MB | 私人库存仅本人；插入公开内容后相应表情可见 |

- 正文必须提示对付款凭证、API Key、手机号、身份证、银行卡号做脱敏。
- 图片资源不得仅靠隐藏按钮实现隔离，媒体接口必须逐次验证作者身份、审核权限和真实发帖状态。
- 表情库上传后只能归入当前用户账号；管理员仅在被授权治理时可查看对应用户表情并禁用或删除；管理员不能管理其他管理员表情。

## 8. Emoji 与私人表情库

- 原生 Unicode Emoji：分类浏览、关键词搜索、最近使用、常见手势肤色；各平台由操作系统字体绘制，无需附带 Apple 专有图形。
- 私人表情支持静态 JPG/PNG/WebP，单文件最多 1 MB，最多保存 200 张；拒绝可执行内容或视频。
- 上传、插入、移除、被禁用/删除均有反馈。插入帖子时后台验证使用者对表情的所有权和启用状态。
- 管理后台展示表情缩略图、上传者昵称/UID、上传时间、启用状态；有 `stickers.remove` 权限者可以通过缩略图右上角红色 × 删除，操作审计必须记录。

## 9. 举报曝光、申诉与内容治理

- 举报需填写类型及详细理由；公开风险线索进入人工审核，管理侧记录审核意见及时间。
- 管理操作：审核待发布帖子、下架已发布帖子、待审评论、隐藏评论、处理内容举报、处理申诉、栏目管理。
- 处理人须提供具体依据，驳回、下架、隐藏、举报/申诉结果写入审计。已下架内容采用软删除以保留申诉证据和处理线索。
- **举报曝光帖同样可以批量审批。** 允许审核员先逐项核验文本、图片及私密证据，然后勾选部分或全选当前队列，一次执行批量批准或批量驳回。批量批准此类内容时，必须明确勾选已完成核验和脱敏的确认项；服务器强制检查并逐条记录。
- 申诉被接受不意味着自动恢复内容，而是进入重新审核队列。
- 公开页面应提示举报内容未经司法认定，禁止未经证实的人身攻击、真实姓名/手机号/API Key 泄露、诽谤和付费删帖。

## 10. RBAC 与后台工作台

| 权限键 | 功能 | 普通管理员 | 超级管理员 |
|---|---|---|---|
| `posts.review` | 审核待发帖子 | 按授权，仅会员 | 全部 |
| `posts.remove` | 下架帖子 | 按授权，仅会员 | 全部 |
| `comments.review` | 审核评论 | 按授权，仅会员 | 全部 |
| `comments.remove` | 隐藏评论 | 按授权，仅会员 | 全部 |
| `reports.review` | 举报处理 | 按授权 | 全部 |
| `appeals.review` | 申诉复核 | 按授权 | 全部 |
| `users.view` | 查看用户 | 按授权 | 全部 |
| `users.mute` | 会员禁言 | 按授权，仅会员 | 会员与管理员 |
| `sections.manage` | 管理栏目 | 按授权 | 全部 |
| `stickers.review` | 查看表情治理 | 按授权，仅会员对象 | 全部 |
| `stickers.remove` | 禁用/删除表情 | 按授权，仅会员对象 | 全部 |
| `audit.view` | 审计日志 | 仅本人 | 全部 |

- 普通管理员无法任免管理员，即使直接请求 `/api/admin/users/:id/permissions` 也必须失败。
- 超级管理员按 UID、昵称或注册邮箱搜索用户，任命、撤销管理员身份并逐项授予权限。
- 禁言支持一小时、一天、七天、永久、解除，以及自定义日历日期与分钟时间；保存为 UTC、显示时按用户时区格式化。
- 角色/权限变更必须立即影响后端能力，前端入口刷新只是便利，并不代替服务端授权。
- 管理员后台标签：总览、待审帖子、帖子管理/下架、待审评论、评论管理、举报处理、申诉复核、会员管理/禁言、栏目管理、表情包治理、操作日志。超管额外有管理员任免和捐赠地址管理。

### 10.1 审核工作台的勾选与批量操作

所有有批量意义的管理列表均提供：单条勾选、全选当前列表、取消全选、已选择数量、批量动作菜单、原因填写、风险确认与逐条结果。一次批量请求最多 100 条，后续页面需继续逐批处理；“全选”并非无上限的全站批处理。后台未授予权限的按钮不得出现，但最终权限判定必须在服务端进行。

| 后台列表 | 可批量动作 | 额外保障 |
|---|---|---|
| 待审帖子（包含举报曝光） | 批量批准、批量驳回 | 批准风险线索或含图片内容需要明确确认人工核验、脱敏 |
| 已公开帖子 | 批量下架 | 逐条检查作者身份与当前发布状态 |
| 待审评论 | 批量通过、批量隐藏 | 风险帖评论或带图评论批量通过需要核验声明 |
| 评论管理 | 批量隐藏 | 保留原文和审计原因 |
| 举报处理 | 批量标记处理、批量驳回 | 普通管理员不得处理涉及其他管理员内容的记录 |
| 申诉复核 | 批量受理、批量拒绝 | 受理后仅退回人工复核，不自动重新公开 |
| 会员管理/禁言 | 批量禁言24小时、批量解除禁言 | 不得禁言自己或超级管理员；普通管理员只能处理普通会员 |
| 栏目管理 | 批量启用、批量停用 | 不自动删除已有关联帖子的栏目 |
| 表情包治理 | 批量恢复、禁用、删除 | 按表情所有者角色逐条校验；删除后访问被阻止 |
| 管理员任免、捐赠配置、审计查询 | 不提供批量修改 | 涉及高敏感授权/资金配置或只读信息，须逐项操作 |

- **API:** `POST /api/admin/batch`；载荷包括 `resource`、`action`、`ids[]`（1～100 个唯一正整数 ID 字符串）、`note`（5～500 字）、`reviewedEvidence`（对批量批准风险线索的明确确认）。
- 后端每条记录单独开启数据库事务、锁定当前记录、检查管理员权限、目标作者角色、状态迁移及操作理由；成功项提交，失败项回滚并返回具体错误，避免一条失败影响其他记录。
- 返回包含同一个 `batchId`、成功与失败数量及每条结果。管理员可在原列表看到结果摘要；每条成功记录的 `audit_logs.details` 带有相同批次编号、操作人、目标、操作前状态、审核理由与核验确认状态。
- **风险曝光帖不禁止批量审批**；“人工已核验”复选框是对审核行为的明确记录，不意味着程序已自动验证该指控真实，也不能替代管理员实际检查。
- 普通管理员不能借批量接口绕过自己没有的逐项权限，不能对管理员发布的帖子或表情执行成员范围之外的处罚。


## 11. 审计日志与运营透明度

每条管理操作最少记录执行时间（UTC）、操作人 UID/昵称及角色、目标类型和目标 ID、动作名称、状态前后、处理原因、适用的脱敏来源 IP 或请求 ID。管理员只能在后台读取自身审计；超级管理员可读取全部。密码、密钥、重置令牌、隐私证据不得写入日志。批量处理还应记录 `batch_id`、核验声明、每个目标的原状态和新状态、原因及是否成功；失败项随 API 响应回传但不能误记成成功。

关键动作包括：角色任免、权限授权/撤销、禁言/解禁、帖子审核/下架、评论隐藏、举报/申诉处理、表情禁用删除、栏目增改删、捐赠地址更改与密码更新。

## 12. 动态栏目管理

- 后台可创建交流栏目、风险曝光栏目或独立内容页面，并设置英文 slug、名称、图标、描述、排序与公开开关。
- slug 不允许随意更改并由服务器校验格式和唯一性。
- 已包含帖子栏目的删除必须受到限制，优先停用；独立页内容以纯文本呈现，不执行用户自填 HTML/JS。
- 关闭栏目不在公开侧边栏出现；普通用户无权新建和编辑栏目。

## 13. 多语言、主题与响应式

- 手动语言切换器提供 24 种界面语言：简体、繁体、英语、日语、韩语、西班牙语、法语、德语、巴西葡语、阿拉伯语、印地语、印尼语、俄语、意大利语、土耳其语、越南语、泰语、马来语、荷兰语、波兰语、乌克兰语、波斯语、乌尔都语等，以实际语言清单为准。
- 不从 IP 或浏览器自动切换，默认简体中文；所有固定 UI 文案，包括页脚、按钮、登录、管理后台应跟随切换；语言切回中文恢复原文。
- 对阿拉伯语、波斯语、乌尔都语支持 RTL；用户撰写的帖子与昵称保留原始语言。
- 网站按钮翻译不等于用户帖子自动翻译。帖子右上角按钮使用可选的 LibreTranslate 服务翻译已公开标题和正文，只要当前语言模型确实可用。
- 日间和夜间主题通过本地用户偏好切换；响应式支持 320px、390px、768px、1024px、1440px 基线，不得溢出页面。

## 14. 公开帖子机器翻译

- 翻译 API 接收目标语言枚举，仅转发已公开的帖子标题与正文，不发送私密证据、登录凭据或原始附件。
- 自建 LibreTranslate 为可选服务，不对公开云端永久免费/全 24 语种可翻译作承诺。
- 翻译结果标注机器翻译仅供参考，可一键恢复原文；限流并在服务端校验目标语言与支持模型。

## 15. 捐赠管理与完整性防护

- 页脚左侧显示“为维持网站正常运营，希望大家积极捐赠加密货币维持运营”和可用捐赠网络及地址；页脚右侧显示公益免责声明和社区公约。

- 公开界面不得向用户推荐个人银行卡付款或宣称捐赠可以换取举报下架、封号或其他审核优待。

## 17. 接口边界和数据安全

- API 族群包括：`/api/auth/*`、`/api/posts*`、`/api/stickers/*`、`/api/media/*`、`/api/reports`、`/api/appeals`、`/api/admin/*`、`/api/site/donations`、`/api/sections`、`/api/stats`、`/api/meta`。
- 所有涉及管理状态修改的接口在后端同时验证登录、角色及权限、目标对象身份、操作状态和审计记录；管理者不能通过篡改按钮 HTML 绕过限制。
- 敏感附件需鉴权访问；上传文件以实际内容验证和重编码；密码/令牌等敏感值不得输出到日志或 API。批量审核权限不能依赖前端勾选，而必须由后端在每个事务中再次校验。
- 用户输入必须设长度和类型限制，HTML 输出转义；数据库操作使用参数化 SQL；所有写请求验证 CSRF 和限流。

## 18. DDoS、安全与部署边界

- 分布式 Redis 滑窗限流用于登录、发帖、评论、上传、找回密码、翻译等接口；Redis 故障时生产限流应拒绝请求而非开放访问。
- 使用 Turnstile 防自动化、HTTPS、严格 Cookie、安全响应头、CSP/输入校验；数据库及 Redis 在内网，外网只见反向代理。
- Cloudflare/WAF 与源站隐藏是抗大流量 DDoS 所必须的基础设施，应用层代码不能保证绝对免攻击。
- 自建服务上线前进行依赖漏洞审计、恶意文件测试、越权测试、备份恢复演练、SMTP 邮件测试和流量压测。
- GitHub 仓库严禁提交 `.env`、生产私钥、SMTP 密码、Turnstile secret、用户数据、上传证据或真实收款配置。

## 21. 修复交付与部署验收

本节为 V3.1 修复交付版的补充要求，原有全量功能与角色边界继续适用。

### 21.1 认证与管理一致性

- 登录、注册和找回密码请求消耗验证码后，保留表单的失败路径必须刷新组件并获取新 token。
- 单条举报、申诉与批量入口执行相同的目标作者身份限制；数据更新、状态校验与审计写入在同一事务中提交，失败全部回滚。
- 评论审核使用受限上下文接口，仅返回有权审核的评论及图片；未公开父帖无权限时不返回其标题正文或私密证据。
- API 时间字段统一输出带 Z 的 UTC 时间；批量参数错误返回 400；存活与依赖就绪检查分离。

### 21.2 翻译资源控制

- 缓存按内容、目标语言、引擎地址和模型版本标识生成，不受浏览次数更新时间影响；同进程相同内容请求合并。
- Redis 共享缓存最多500条，缓存有效期30分钟；单进程默认2个翻译任务，最多排队32个，排队超时15秒，上游单请求超时30秒。
- 实际模型能力由接口公布，未安装语言不允许请求；巴西葡萄牙语使用 pb。源语言和中转路径仍由真实模型决定。
- 允许配置受控私网IPv4地址或显式允许的内部DNS，翻译端口仅允许网站机访问；多实例需合计推理并发。

### 21.3 部署和交付验证

- 提供 package-lock.json，使用 npm ci；sharp 固定到0.35.5，公开前再次审计。Docker预建并赋权两个上传目录，旧卷单独检查。
- 数百人多语言场景起步预算为网站8核16GB RAM，翻译8核16GB至16核32GB，SSD各100–200GB；这是预算，不是压测通过的容量保证。
- 在Node 22.23.5上，48项本地Node测试通过，包括HTTP路由与事务替身、JPG/PNG/WebP重编码；官方依赖审计0条已知漏洞。浏览器验证离线预览及正式前端的替身接口流程。
- 未提供真实服务器，Linux Docker、MySQL、Redis、SMTP、Turnstile、真实模型及数百人压测仍须部署时验收，不将替身测试写成生产联调通过。

## 22. V3.2 置顶与页脚联系方式

版本为 v1.1.0，研发名称 V3.2 功能增强版。本版基于已修复的 v1.0.1 增量修改，保留其余功能。外层五个文件沿用原文件名（包括 V3.1），以内部版本号识别本次更新。

| 功能 | 超级管理员 | 管理员 | 普通会员 |
| --- | --- | --- | --- |
| 社区首页置顶 | 可设置 | 禁止 | 禁止 |
| 首页之外的帖子列表置顶 | 可设置 | 可设置 | 禁止 |

进入管理员后台的「帖子置顶」标签；超管看到首页、板块两个独立开关，管理员仅看到板块开关。只允许处理已公开帖子，可搜索和翻页。板块置顶适用于举报曝光、交流讨论及各讨论栏目中本来符合筛选条件的帖子，不把帖子跨栏目复制。独立内容页没有帖子列表。搜索结果和「我的帖子」继续使用原顺序。置顶帖子优先显示，同组仍按新帖或热度排序；允许多条置顶。下架或驳回会清除两种置顶，重新发布时不自动恢复。新增板块置顶是管理员角色能力，可用于任意已公开作者的帖子；原有审核、删除及禁言的作者层级规则不变。

超管进入「超级管理员后台 → 页脚联系方式」，启用总开关，最多添加4行不同类型，左侧选 QQ、Telegram、X、TikTok、微信、Discord、WhatsApp、邮箱或其他，右侧填账号/号码。每行也可独立关闭；空行请关闭或移除。保存后在页脚底部中间竖向显示，手机端自动换行。关闭总开关后公开页为空，公开接口不返回后台保留的号码。配置带签名、版本冲突检查和审计，审计不保存号码。前端按纯文本显示，不执行填写内容中的 HTML。

## 从 v1.0.1 升级到 v1.1.0

新安装使用空数据卷与最新 database/schema.sql，已包含置顶字段；不要再运行007。已有 V3.1 修复版先备份数据库、上传与表情卷并确认可恢复，停止 app 写入，**只执行一次 database/migrations/007-v3.2-pins.sql**，再更新镜像并启动 app。该脚本新增两个默认0的字段及索引，不删除原数据；已有数据卷不会自动迁移。更早版本先补齐此前缺失迁移。不要对生产旧库运行全量 schema.sql，也不要执行 docker compose down -v。

Linux / Docker Compose 下，在正确项目目录和已载入正式环境配置的前提下执行（已有 v1.0.1 数据库）：

```bash
docker compose stop app
docker compose exec -T db sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" exec mysql -u"$MYSQL_USER" "$MYSQL_DATABASE"' < database/migrations/007-v3.2-pins.sql
docker compose up -d --build app
docker compose ps
curl -fsS http://127.0.0.1:3000/api/health
```

确认迁移成功后再启动新版应用；遇到 Duplicate column 表示字段可能已存在，先核对数据库版本与字段，不盲目重跑。回滚应用可保留新增字段和原数据，数据库回滚按已验证备份方案实施，不直接删卷。验收超管/管理员/会员权限、置顶顺序、下架清除、联系方式关闭和并发保存。
